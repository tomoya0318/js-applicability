# 着手ブロッカーと未決定事項

このファイルは、この handoff 文書群のスコープ、つまり次プロジェクトの**設計と実装に着手するために決める必要がある事項**をまとめたものです。
各項目には、決める内容と、決まらない場合に止まる作業を記します。

論文レベルの未決の正本は、別リポジトリの`my-research/open-questions.md`です。
あちらは`current.md`の版管理と一体の決定ログで、日付付きの整理履歴（closed / 新規 / 昇格 / 降格）を持ちます。
このファイルは履歴を持たない着手ゲートであり、役割が異なります。内容を複製せず、必要なものは出典で参照します。

外部確認データ（案A）と、`current.md`で既に決着している事項は末尾の除外一覧に回します。

## 前処理契約

| 項目 | 何を決める必要があるか | 決まらないと何が進まないか |

| 対象コードへの到達の観測 | before / afterの対象コードに到達したことを、フック、観測値、実行トレースなどのどの証拠で判定するかを決めます。 | プロセス終了だけで見かけ上のequalになったケースを除外できません。 |
| 依存関係と`inconclusive`の契約 | 依存関係をどこまで固定し、依存不足、初期化失敗、観測不能などをどの状態に分類するかを決めます。 | 再現可能な実行環境を作れず、失敗と判定不能を正しく分離できません。 |
| slicingの採用 | slicingをそのまま採用するか、依存閉包を作る前処理のどの段階で使うかを決めます。 | 大きな入力コンテキストを静的に縮約する方式を確定できません。 |
| HDD / ddminの適用段階 | HDDやddminを静的整理の前後のどの段階で使うかを決めます。 | 動的削減を適用する対象と、試行回数の見積もりを決められません。 |
| 依存閉包の構築方法 | 依存閉包を静的解析だけで作るか、実行トレースを併用するかを決めます。 | import / require、自由変数、制御依存を残す基準を実装できません。 |
| 最小化の停止条件と予算 | 最小化を止める条件と、ケースごとの実行試行予算を決めます。 | 前処理が終了しないケースを制御できず、実行時間を評価指標として比較できません。 |
| 必須とする副作用 | どの副作用を実行可能性の必須条件に含めるかを決めます。 | 戻り値以外の観測を要するケースで、観測可能性を保証する前処理契約を確定できません。 |

## 解決済みとして除外した項目

- 外部確認データ（Selakovic外OSS・案A）の継続可否：[current.md「当面の作業順」](../current.md#当面の作業順)により当面見送りと決まり、論文の質が要求する場合だけ復活します。
- RQ1の主評価単位：[current.md「RQ1の検証方法」](../current.md#rq1-の検証方法)でパターン単位（N=10）と決まり、issue単位の再現安定性は別指標として扱います。
- 初期実行プロファイルの構成：CommonJSを初期対象とし、browser / jsdomはCommonJSのfallbackではなく必要時に追加する独立契約と決まりました。
- ESM・TypeScript対応の扱い：初期スコープ外とし、論文では適用範囲の境界として未対応ケース数と除外理由を報告します。
- JSONLの出力順：`id`昇順に固定します。逐次でも並列でも成り立ち、コストがゼロです。固定しないと並列化した時点で行順が非決定的になり、全再実行の差分が読めなくなります。
- Nodeバージョンの記録先：`out/NN-stage.run.json`にステージ実行単位で1個記録し、summaryの全行には書きません。1ステージの実行は1プロセスで`process.version`が不変なので、記録の粒度をそこに合わせます。`mise.toml`での固定は代替になりません。固定が効くのはmise経由の実行だけで、直打ちは固定の外にあるためです。
