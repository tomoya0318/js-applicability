# 出力

`<work-dir>/review.md` の「実装検証」節へ次の表で書いてください。

| # | 分類 | 指摘 | file:line | 確信度 | 事前検出 | 突き合わせるべきだった正本 | 対応 |

- 分類 … `欠陥` / `要件外` / `要件誤り`
- `欠陥` … `要件` を満たしていない、または壊している
- `要件外` … どの `要件` にも紐付かない変更。良し悪しは判定せず、事実として挙げる
- `要件誤り` … `要件` の記述そのものが現物と食い違う。コードではなく要件を直す対象
- 確信度 … 高・中・低。現物で確かめたものと、コードを読んだだけの推測を混ぜない
- 事前検出 … **`可` / `不可`**。実装前に `plan.md` と追跡済みファイルだけで検出できたか
- 突き合わせるべきだった正本 … 事前検出が `可` のとき、`plan.md` と突き合わせれば
  食い違いが出たはずの追跡済みファイルのパス。**必ずパスで書く**。`不可` のときは空欄
- 対応 … 空欄のままにする。人間が埋める

1行に収まらない指摘は、表に要約を書き、表の下へ `### N.` の見出しで詳細を書いてください。

`事前検出` は全分類に付けてください。**この列は skill と plan の書き方を直すために使います。**
`不可`（実装するか実行するかしないと分からなかった）なら、そう書いてください。
`可` を無理に埋める必要はありません。
