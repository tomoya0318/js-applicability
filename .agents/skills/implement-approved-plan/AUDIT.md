## 落とした工程

各行は `<fork 元の見出しまたは手順の逐語引用> — <落とした理由>` の形にする。
逐語引用は `skill-lint` が fork 元と照合するので、要約しない。

- ## 計画の単位 — plan は main で承認済みなので、単位の判定を持たない
- ## 計画の構成 — 同上。`plan.md` の書式は書き手側の規律であり、読み手は持たない
- ## 書き方 — 同上
- ## 規模の判定 — effort を `xhigh` に固定した。下げてよい条件を書くと毎回下がる
- 1. 作業名は英語のハイフン区切りで渡す — 作業ディレクトリ名は main で決まっている
- 2. Plan エージェントに調査を委譲する — 調査は main の計画段階で済んでいる
- 3. main が調査結果から `plan.md` を書く — plan を書くのは main である
- 4. ユーザーが計画検証を求めた場合のみ — 計画検証は main 側で行う
- 5. 手順4を行った場合は、指摘を計画へ反映し — 同上
- 6. `plan.md` のパスをユーザーへ伝え — 承認は main で得ている
- ## ADR — 着地時に `land-worktree` が行き場として扱う

## 落としていないが形を変えたもの

- `## 検証の実行` は「ユーザーが明示的に求めたときだけ行う」だが、こちらは手順 5 で必須にした。
  コミット本文が `要件` の台帳になるため、任意にすると誤った要件が台帳に残る
- `## バイアス分離` は節としては無いが、4 文のうち 2 文は形を変えて持っている。
  `検証を行うときは、実装したインスタンスと別の fresh な codex に依頼する。` は手順 5 の
  「実装した tab を使い回さない」、`検証者には指摘だけをさせ、手を動かさせない。` は
  骨組みの「指摘だけを行い、ファイルを変更しないでください」に対応する。
  残る 2 文は落ちていたので戻した (骨組みへ「現物で確認する」、手順 5 へ「重ねて読み直さない」)
